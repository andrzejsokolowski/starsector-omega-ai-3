# No active control in local build 0.2.0

The user reported no ship labels or visible Omega decisions.
The installed build was Omega AI 0.2.0.
Saved settings had Enable Omega AI, both fleets, simulator support, status, and labels enabled, with mode Coordinate.

The mission log reported 11 readable ships, zero selected ships, and zero actively steered ships at every ten-second sample from t=10 through t=80.
It reported no Omega installation or helm error in that interval.
The lack of labels therefore matched a lack of active control.

The installed AI Tweaks settings had Only Player Assist disabled and all Custom AI options disabled.
Its installed picker still selects ExtendedShipAI for ordinary eligible ships in that configuration.
RTSAssist's installed source hooks friendly ship AI at deployment, including before an RTS movement command.
Omega 0.2.0 rejected both controllers, including Starsector wrappers around them.
The old log omitted per-ship exclusions, so it cannot establish the exact exclusion for each of the 11 ships.

Local build 0.2.1 replaces the mode selector with one enable switch and ignores saved Observe selections.
It recognizes Starsector's native transparent wrapper, names AI Tweaks and RTSAssist exclusions, and reports inactivity reasons in the combat HUD.
It does not add support for those two third-party controllers.
The gameplay guide specifies only Omega AI, LunaLib, and LazyLib, with Search & Destroy and flagship autopilot.
No game settings, installed mods, or saved games were modified during this investigation.
